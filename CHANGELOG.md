## 2026.11.07

Owner questions on MGR-77 parity, answered in the browser on tcs and bb (both local, kit 2026.11.06.5).

- **Why the shop grid had 4 columns on tcs and 3 on bb at the same width, measured.** The kit's `repeat(auto-fill, minmax(min(100%, 13.5rem), 1fr))` is a drifting rule: bb at 1440 has a 934px results column and a 24px gap, and four 216px columns need 936px, so it fell to 3 (at 1024: 2 columns); tcs got 4 from its OWN rule `.woocommerce ul.products.columns-4 { repeat(4, 1fr) }` (site.css, "WooCommerce marks a four-wide list...", it beat the kit's rule on specificity because WooCommerce's "products per row" setting puts `columns-4` on both lists) and had a 32px gap from its `--pkde-shop-gap`, so 4 columns of 152px at 1024. Not the root font size (16px both) or `--container-content` (80rem both).
- **The grid has a fixed column count from kit variables:** `--pkde-shop-columns` (from 1280px, the filter column beside the results; default 4), `--pkde-shop-columns-tablet` (640px to 1279px; 3), `--pkde-shop-columns-phone` (below 640px; 2), the same on every site, with the column gap `--pkde-shop-gap` (1.5rem) and a selector more specific than any `.woocommerce ul.products.columns-N` or `.page-content .woocommerce.columns-N ul.products` rule. 4 at desktop with the sidebar is not too tight: a card is 216px wide at 1440 (the same as the 3-column look's neighbour at 1280: 217px); at 1024 the sidebar leaves 680px, so 3 columns of 211px (4 would be 152px, which tcs showed).
- **The space at the top was 15px taller on tcs, and it was the breadcrumb trail.** Rank Math prints the trail as a `<p>`; tcs's theme.json gives every `p` 1.0625rem and a 1.85 line height (`:root :where(p)`), so the trail's line was 31px instead of 16px; bb has no such style. `.breadcrumbs p` now takes the trail's own font and line height. Everything else was equal (the band's padding, the notices wrapper at 0px height, the toggle and the filter column offsets, 111px from the band to the layout on both). The band's space is now `--pkde-page-header-padding` (3.5rem) and `-lg` (4rem from 640px), and the space above the filters `--pkde-shop-pad-top` (1rem): kit variables only; the `py-14 sm:py-16` classes are gone from the view.
- **Measured (a category archive, kit CSS injected into the live pages, both sites):** 1440: 4 columns of 216px, gap 24px, band 217px, trail 16px, band to layout 111px, on both. 1024: 3 columns of 211px, band 217px, band to layout 102px, on both. 390: 2 columns of 159px, band 186px, band to layout 95px, on both. Before: tcs 4 / 4 (152px) / 1 columns and a 232px band, bb 3 / 2 / 1.
**Adopt:** bump the kit. **Delete in tcs `site.css`:** the `.woocommerce ul.products.columns-4 { ... }` rule (and its comment) and the `--pkde-shop-gap` line (the kit's 1.5rem is the standard). **Delete in bb `site.css`:** the `.page-content .woocommerce.columns-4 ul.products { ... }` rule. Neither site needs to set `--pkde-shop-columns` (4 is the default).
