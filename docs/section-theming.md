# Section theming

Every palette colour (see [Re-branding: colour & font tokens](branding-tokens.md)) is also a
re-themeable **section** — add a `theme-{name}` class (or the brand-agnostic `theme-{alias}`
alternative, below) to any element, and everything inside it that reads the `--pkde-theme-*`
custom properties re-skins together: background, text, and button colours all switch from one
class. Generated by the same `bin/generate-theme-tokens.mjs` into `generated/section-themes.css`
— nothing to hand-author per client.

```css
/* generated/section-themes.css (one block like this per palette colour) */
.theme-brand,
.theme-alpha {
  --pkde-theme-background: var(--color-brand-600);
  --pkde-theme-content: var(--color-white);
  --pkde-theme-highlight: var(--color-brand-200);
  --pkde-theme-btn-bg: var(--color-white);
  --pkde-theme-btn-text: var(--color-brand-700);
  --pkde-theme-btn-border: var(--color-white);
  --pkde-theme-alt-btn-bg: transparent;
  --pkde-theme-alt-btn-text: var(--color-white);
  --pkde-theme-alt-btn-border: var(--color-white);
  --pkde-theme-border: var(--color-brand-500);
}
```

**Two ways to address the same theme, on purpose:**

- **By name** (`theme-brand`, `theme-danger`, `theme-campaign-green`) — for anyone who already
  knows this client's palette vocabulary.
- **By a brand-agnostic positional alias** (`theme-alpha`, `theme-bravo`, `theme-charlie`, ...,
  the NATO alphabet, assigned in `config/brand-palette.json`'s array order) — for a dev who
  doesn't, or for template/demo code (like the block demo page) that has to work across any
  client's actual colour names. Both selectors are written into the same CSS rule, so
  `theme-brand` and `theme-alpha` are never out of sync — they're the exact same theme. Reordering
  the palette array reassigns which colour an alias points to, so treat aliases as positional, not
  as stable identifiers if you ever hand-edit `config/brand-palette.json`.

**Components must consume only the `--pkde-theme-*` tokens, never a raw `--color-{name}-*` value
directly** — that indirection is the entire mechanism. `app.css` defines the `:root` fallback
(this template's plain dark hero/CTA look, so an element with no theme class at all still renders
correctly) plus two ready-to-use button classes, `.pkde-btn` (primary) and `.pkde-btn-alt`
(secondary/outline), and a `.pkde-section` background+text pairing. The **Hero block** (see
[the blocks README](../resources/blocks/README.md)) is the first real consumer: its own "Section
theme" panel in the block editor picks a theme by name or alias, with no other markup change
needed. The block demo page seeds it four times (no theme, then
`theme-brand`/`theme-accent`/`theme-charlie`) so the effect is visible immediately after a fresh
`bin/setup` run.

Only the Hero block is wired up so far — the other seven blocks are grids of cards, where
"theme the section" is a different, not-yet-decided design question (recolour every card, or just
a wrapping heading/background?) rather than a drop-in extension of this same pattern.
